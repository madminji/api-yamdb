# api_yamdb
`api_yamdb` — это бэкенд и REST API для сервиса **YaMDb**, который собирает отзывы пользователей на произведения (книги, фильмы, музыку). Сами произведения в YaMDb не хранятся — здесь нельзя посмотреть фильм или послушать музыку.

Произведения делятся на категории и могут быть отнесены к одному или нескольким жанрам. Пользователи оставляют к произведениям текстовые отзывы и ставят оценку от 1 до 10; из оценок формируется усреднённый рейтинг произведения. На одно произведение пользователь может оставить только один отзыв. К отзывам можно оставлять комментарии.

В проекте реализованы два основных приложения:
- `reviews` — модели пользователей, произведений, категорий, жанров, отзывов и комментариев;
- `api` — REST API для работы с данными проекта

## Технологии

- Python 3.12
- Django 5.1.1
- Django REST Framework 3.15.2
- Simple JWT (JWT-аутентификация)

## Возможности API

- Регистрация пользователей через email с подтверждением кодом и получение JWT-токена.
- Управление пользователями, произведениями, отзывами и комментариями; просмотр, создание и удаление категорий и жанров.
- Гибкая система прав доступа: анонимный пользователь, аутентифицированный пользователь, модератор, администратор.
- Автоматический расчёт рейтинга произведения по отзывам.
- Импорт начальных данных из CSV-файлов в базу данных.

## Пользовательские роли

| Роль | Права |
|---|---|
| **Аноним** | Может читать описания произведений, отзывы и комментарии |
| **Пользователь (`user`)** | Всё, что доступно анониму, + публикация отзывов и оценок, комментирование, редактирование/удаление **своих** отзывов и комментариев |
| **Модератор (`moderator`)** | Права пользователя + редактирование и удаление **любых** отзывов и комментариев |
| **Администратор (`admin`)** | Полные права на управление всем контентом проекта, включая категории, жанры, произведения и пользователей |

Суперпользователь Django всегда обладает правами администратора, независимо от значения поля `role`.

## Установка и запуск проекта

1. Клонировать репозиторий и перейти в него в командной строке:

```bash
git clone git@github.com:madminji/api-yamdb.git
cd api_yamdb
```

2. Создать и активировать виртуальное окружение:
```bash
python -m venv venv
# Windows
source venv/Scripts/activate
# Linux/macOS
source venv/bin/activate 
```

3. Установить зависимости:
```bash
pip install -r requirements.txt
```

4. Выполнить миграции:
```bash
python manage.py migrate
```

5. Заполнить базу данных тестовыми данными из CSV-файлов (директория `static/data`):

```bash
python manage.py import_data
```

6. При необходимости создать суперпользователя:

```bash
python manage.py createsuperuser
```

7. Запустить проект:

```bash
python manage.py runserver
```

- API будет доступен по адресу `http://127.0.0.1:8000/api/v1/`
- Документация (Redoc) — по адресу `http://127.0.0.1:8000/redoc/`

## Основные эндпоинты
 
| Эндпоинт | Описание |
|---|---|
| `/api/v1/auth/signup/` | Регистрация и получение кода подтверждения |
| `/api/v1/auth/token/` | Получение JWT-токена |
| `/api/v1/users/` | Управление пользователями (только администратор) |
| `/api/v1/users/me/` | Просмотр и редактирование собственного профиля |
| `/api/v1/categories/` | Список и создание категорий |
| `/api/v1/categories/{slug}/` | Удаление категории |
| `/api/v1/genres/` | Список и создание жанров |
| `/api/v1/genres/{slug}/` | Удаление жанра |
| `/api/v1/titles/` | Список и создание произведений |
| `/api/v1/titles/{title_id}/` | Получение, изменение, удаление произведения |
| `/api/v1/titles/{title_id}/reviews/` | Список и создание отзывов |
| `/api/v1/titles/{title_id}/reviews/{review_id}/` | Получение, изменение, удаление отзыва |
| `/api/v1/titles/{title_id}/reviews/{review_id}/comments/` | Список и создание комментариев |
| `/api/v1/titles/{title_id}/reviews/{review_id}/comments/{comment_id}/` | Получение, изменение, удаление комментария |

## Фильтрация
 
Для произведений (`GET /api/v1/titles/`) доступна фильтрация через query-параметры:
 
| Параметр | Описание |
|---|---|
| `category` | фильтрует по slug категории |
| `genre` | фильтрует по slug жанра |
| `name` | фильтрует по названию произведения (частичное совпадение) |
| `year` | фильтрует по году выпуска |
 
Пример:
```
GET /api/v1/titles/?genre=fantasy&year=2001
```
Ответ:
``` json
{
    "count": 1,
    "next": null,
    "previous": null,
    "results": [
        {
            "id": 7,
            "name": "Властелин колец: Братство кольца",
            "description": "",
            "year": 2001,
            "genre": [
                {
                    "name": "Фэнтези",
                    "slug": "fantasy"
                }
            ],
            "category": {
                "name": "Фильм",
                "slug": "movie"
            },
            "rating": 4
        }
    ]
}
```

## Примеры запросов к API

### Регистрация нового пользователя
```
POST /api/v1/auth/signup/
```
 
```json
{
  "email": "user@example.com",
  "username": "user_name"
}
```
На указанный email придёт письмо с кодом подтверждения. В текущей конфигурации (`EMAIL_BACKEND = 'django.core.mail.backends.console.EmailBackend'`) реальная отправка почты не выполняется, письмо выводится прямо в консоль, в которой запущен `python manage.py runserver`. Там и нужно искать `confirmation_code`.

### Получение JWT-токена
 
```
POST /api/v1/auth/token/
```
 
```json
{
  "username": "user_name",
  "confirmation_code": "confirmation-code-from-email"
}
```
Ответ:
```json
{
  "token": "string"
}
```

Полученный токен передаётся в заголовке каждого авторизованного запроса:
 
```
Authorization: Bearer <токен>
```

```
POST /api/v1/titles/{title_id}/reviews/
```
 
```json
{
    "text": "User review",
    "score": 4
}
```

```json
{

    "text": "User review",
    "author": "regular-user",
    "score": 4,
    "pub_date": "2026-06-28T12:55:27.321969Z"
}
```

```

    "text": "User comment"
}
```
